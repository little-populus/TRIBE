# IABA 专项报告：批内迭代适应（Iterated Intra-Batch Adaptation）

> **一句话**：让模型对同一批测试数据"多看几遍、每遍重新校准"，在不增加任何标注、不修改网络结构的前提下，把 CIFAR-10-C 上的准确率从 **78.99% 提升到 86.85%**（+7.86pt）。
>
> 本报告面向**没有接触过测试时适应（TTA）**的读者：每个专业术语第一次出现时都会给出通俗解释。
> 所有数字均为本机实测（RTX 5070 Ti，CIFAR-10-C，severity 5，GLI-TTA-F 协议）。

## 0. 一分钟版本

**背景**：一个在干净照片上训练好的图像分类模型，遇到雨雪、模糊、噪声等"真实世界"照片时准确率会大幅下降。**测试时适应（TTA）** 指的是：模型在测试阶段、**只看到无标签的新数据**，就地进行自我调整。

**发现的问题**：TTA 方法每次切换到一个新场景（比如从"雾天"切到"雪天"），**头几十个样本的预测几乎全错**——实测第一个批次准确率只有 **53.2%**，而同一场景稳定后是 **81.1%**，差 **28 个百分点**。原因是模型"先答题、后校准"：它在用上一个场景的旧参数回答新场景的问题。

**我们的方法（IABA）**：对每一批测试数据，把"预测 → 校准 → 再预测"这套动作**重复 K 次**，只把最后一次的答案交出去。K=1 就是原方法。

**效果**（CIFAR-10-C，15 种损坏，按类别平均后）：

| 每批迭代次数 K | 1（原方法） | 2 | 3 | 4 |
|---|---|---|---|---|
| 准确率（逐样本） | 78.99 | 82.57 | 85.08 | **86.85** |
| 准确率（逐类别平均） | 77.48 | 81.52 | 84.63 | **86.81** |

**代价**：计算时间随 K 线性增长（K=4 时 0.014 s/样本，仍低于 CoTTA 的 0.019），显存**不增加**，代码改动只有一个循环。

## 1. 背景：读懂本报告需要的五个概念

### 1.1 概念一：模型会"水土不服"

想象一个只在晴天拍的照片上训练出来的交警识别系统。晴天照片清晰、光线充足，它认得准。但如果下雨、起雾、镜头抖动、照片被压缩得很糊，像素分布全变了——模型没见过这些，准确率就会掉。

学术上管这种"照片变脏"叫 **corruption（损坏 / 腐蚀）**。本报告用的测试集 CIFAR-10-C 包含 **15 种损坏**：

| 类别 | 具体损坏 |
|---|---|
| 噪声类 | 高斯噪声、散粒噪声、脉冲噪声 |
| 模糊类 | 高斯模糊、散焦模糊、运动模糊、玻璃模糊、缩放模糊 |
| 天气类 | 雪、霜、雾、溅射（水渍 / 泥点） |
| 数字类 | 对比度、亮度、JPEG 压缩、像素化 |
| 其他 | 弹性形变 |

每种损坏有 5 个严重程度，本报告全部使用**最严重的 severity 5**。

> 通俗说法：**模型不是不聪明，是"眼镜度数"不对了。** TTA 要做的，就是在没有验光师（标签）的情况下，让它自己把度数调回来。

### 1.2 概念二：TTA（测试时适应）

正常训练模型需要**标签**（这张图是猫）。TTA 的场景更苛刻：

- 模型已经训练好了，权重不能大改；
- 测试数据**只有图片、没有标签**；
- 数据是一条一条（或一批一批）流过来的，模型要**边用边调**；
- 调完立刻要给出预测，没有"先收集一万张再统一训练"的奢侈。

> 类比：**一个外派到新城市的司机。** 他不能重新考驾照（不重训练），也没有人告诉他目的地在哪（无标签），只能靠观察路况一点点修正自己对"这里怎么开车"的判断。

TTA 的价值在于：真实世界里，标注永远是瓶颈，而环境变化是常态。

### 1.3 概念三：BatchNorm——模型的"校准尺"

现代卷积网络里几乎每层卷积后面都跟一个 **BatchNorm（批归一化，简称 BN）**。它的作用很朴素：

> 把这一层输出的数值**拉回到统一的尺度和范围**（均值 0、方差 1），再交给下一层。

为什么要拉？因为如果某层输出一会儿是 0.001 量级、一会儿是 1000 量级，后面的层就没法用同一套参数处理。BN 相当于给每一层配了一把"尺子"，保证刻度一致。

关键点：BN 需要知道"当前的均值和方差是多少"。它维护两个数字：

- **running_mean / running_var（运行时统计量）**：训练时用滑动平均记录下来的"典型均值和方差"，测试时直接拿来用。
- **momentum（动量）**：更新这个滑动平均的速度。动量 0.01 的意思是"每次只把旧值往新观测挪 1%"。

> 通俗说法：**BN 的统计量就是模型的"色温白平衡"。** 换了光源（新的损坏类型），白平衡就偏了；TTA 里最常用的一招，就是让 BN 用新数据重新校准白平衡。

**这就是关键**：BN 的统计量是**可以只用无标签数据更新**的——只要前向跑一遍，就能算出这一批数据的均值和方差。所以 BN 天然是 TTA 的抓手。

### 1.4 概念四：类不平衡（长尾）与 I.F.

真实世界的数据流往往不是"每类一样多"。比如城市监控里，普通轿车远多于救护车。

- **I.F.（Imbalance Factor，不平衡因子）**：最多类的样本数 ÷ 最少类的样本数。
  - I.F.=1 → 完全均衡（每类一样多）
  - I.F.=10 → 最多类是最少类的 10 倍
  - I.F.=100 → 100 倍，最稀的类每个场景只有 **10 张**图
- **长尾**：按样本数从多到少排序画柱状图，形状像一条长长的尾巴——少数几个"头类"占了大部分样本，"尾类"样本极少。

本报告用三个设置来考察方法在不同不平衡程度下的表现：**I.F.=1 / 10 / 100**。

**两种评测指标**（这两个指标必须一起看，否则会被误导）：

| 指标 | 算法 | 通俗解释 | 偏向谁 |
|---|---|---|---|
| **micro（逐样本）** | 所有样本一视同仁，算总正确率 | "全部图片里答对了几成" | 偏向**头类**（样本多，权重大） |
| **macro（逐类别）** | 先算每一类的正确率，再对类别取平均 | "每一类平均答对几成" | 每类**等权**，能暴露尾类被牺牲 |

> 为什么两个都要看：一个模型可以靠"把所有尾类都猜成头类"刷高 micro，但 macro 会很难看。**长尾场景下 micro 高而 macro 低，说明它在牺牲少数类。**

### 1.5 概念五：TRIBE——本报告的基线方法

TRIBE（AAAI-24）是我们要改进的方法。它由三个网络组成，理解这三个角色是理解后面一切的前提：

```
                      ┌─────────────────────────────────────┐
   测试批次 x  ──────► │  ① Teacher（教师 / aux_model）       │ ──► 伪标签 p̂ + 最终预测
   （无标签）          │     权重 = 正在被优化的权重           │
                      │     BN 统计 = 逐类维护的"均衡"统计     │
                      └─────────────────────────────────────┘
                                    │
                                    │ 用 p̂ 当"标准答案"
                                    ▼
                      ┌─────────────────────────────────────┐
                      │  ② Student（学生 / model）           │ ──► 输出，算交叉熵损失
                      │     同一套权重，但输入的是强增强图像   │
                      └─────────────────────────────────────┘
                                    │
                                    │ 与锚做对比，算 MSE 损失（防跑偏）
                                    ▼
                      ┌─────────────────────────────────────┐
                      │  ③ Anchor（锚 / source_model）       │ ──► 参照输出
                      │     权重永久冻结（初始的源模型）       │
                      └─────────────────────────────────────┘
```

三个角色的通俗分工：

- **① 教师**：给出"我认为这图是什么"的参考答案（叫**伪标签 pseudo-label**，因为它不是真标签，是模型自己猜的）。
- **② 学生**：看着"加了干扰的同一张图"（强增强），努力复现老师的答案。目的是让模型学到**不依赖具体干扰的稳健特征**。
- **③ 锚**：一个**永不改变的初心**。它不参与学习，只负责在旁边说"别忘了你原本是怎么看世界的"。如果教师越学越野，与锚的差距就会变大，损失随之上升，把它拉回来。

> 类比：**老师带学生做练习，旁边坐着一位不肯改变立场的老教授。** 老师出参考答案，学生照着练，老教授负责提醒"别把基本功练歪了"。这个"老教授"就是防止**确认偏差**（confirmation bias，指模型不断强化自己的错误猜测，越错越自信）的安全绳。

**TRIBE 的另外两个特色**（本报告的改进不涉及，但需要知道）：

1. **Balanced BN（均衡批归一化）**：普通 BN 用整批数据算一个统计量，头类样本多就把统计量带偏。TRIBE 改成**每类各维护一份统计量**，预测时对各类统计量**等权平均**——这样尾类不会被头类淹没。
2. **三网络结构**：三份独立但同步的 BN 统计量，降低"过度适应当前批次"的风险。

**可训练参数只有 BN 的缩放和偏移**（约几万个数字），卷积核权重全部冻结。这一点很重要：说明 TTA 在这里做的是"微调校准"，不是"重新学习"。

## 2. 问题：换考卷的头几道题总是做错

### 2.1 怎么发现的

测试流是这样组织的：15 种损坏**依次**出现，每种 10,000 张（长尾裁剪后见下表），处理完一种再换下一种。每次切换，都是一次"换考卷"。

我们写了一个诊断脚本（`scripts/diag_warmup.py`，约 100 行），它做一件很简单的事：**记录每个场景内"第几个批次"的准确率**，然后按批次序号聚合。

### 2.2 实测数字

I.F.=10 协议下，场景切换后的准确率演化：

| 场景内批次进度 | 准确率 |
|---|---|
| 第 1 个批次 | **53.2%** |
| 随后几个批次 | 60.6% |
| | 69.3% |
| | 76.6% |
| 约 20~30 个批次后（稳态） | **81.1%** |

**第一个批次比稳态低 28 个百分点。** 整段"爬坡期"（从 53% 爬回 81% 的过程）合计拖累总准确率约 **1.7~2 个百分点**——这几乎等于好几篇 TTA 论文互相之间比拼的全部差距。

> 通俗说法：**每次换考卷，前二三十道题都在用上一门课的知识答。** 等它终于"进入状态"，这个场景已经考完一小半了。

### 2.3 根因：先答题，后校准

这不是模型笨，是**顺序错了**。看原始实现的执行顺序（`core/adapter/TRIBE.py` 的 `forward_and_adapt`）：

```
第 1 步：用【旧统计量】做预测       ← 答案在这里已经定死了
第 2 步：用【新数据】更新统计量     ← 校准发生在这里，但答完题了
第 3 步：反向传播微调 BN 参数
```

也就是说，**第一批数据的预测，用的是上一个场景的"白平衡"**。新场景的图片在旧白平衡下被归一化，特征分布完全错位，预测自然接近随机。

而更糟的是：这个错误的预测又被当成**伪标签**，用来更新统计量和训练学生。于是错误在批内自我强化——这就是前面说的**确认偏差**。

## 3. 方法：IABA 到底是什么

### 3.1 一句话与类比

> **既然"先答题后校准"会答错，那就把顺序改成"答一次 → 校准 → 再答一次 → 再校准 → ……"，用最后一次的答案。**

- 通俗类比：**拍照的实时取景。** 第一张拍糊了，你看一眼、调一下焦距，再拍一张；再调、再拍。最后交出去的是最后那张，不是第一张。
- 另一个类比：**空调的自动调温。** 室温 30 度，你设 25 度。空调不会一步到位（那会过冲），而是"测一次 → 调一点 → 再测 → 再调"，逐次逼近。IABA 就是让 BN 统计量在**同一批数据**上做这种逐次逼近。

### 3.2 形式化写法

原方法（K=1）对每个批次 $x$ 只做一次：

$$z = T_{\theta, S}(x), \qquad S', \theta' \leftarrow \mathcal{A}(z, x)$$

IABA（K 次）改为：

$$z^{(k)} = T_{\theta^{(k-1)},\, S^{(k-1)}}(x), \qquad S^{(k)}, \theta^{(k)} \leftarrow \mathcal{A}\left(z^{(k)}, x\right), \quad k = 1,\dots,K$$

最终只返回 $z^{(K)}$。

符号含义（不用记，看懂"下标在变"就够）：

| 符号 | 含义 | 通俗解释 |
|---|---|---|
| $x$ | 当前测试批次（无标签） | 这沓新照片 |
| $T_{\theta,S}$ | 教师网络，$\theta$ 是可训练参数，$S$ 是 BN 统计量 | 那位"出答案的老师" |
| $z^{(k)}$ | 第 k 轮给出的预测（logits） | 第 k 次交的答卷 |
| $\mathcal{A}$ | 一次"校准 + 微调"操作（更新 $S$ 和 $\theta$） | 调焦距 + 微调参数 |
| $K$ | 每批迭代次数（配置项 `OPTIM.STEPS`） | 同一批拍几次 |

**关键在于上标的递进**：第 k 轮预测用的是 $S^{(k-1)}$——**已经吸收了本批数据信息的统计量**。而原方法里，预测用的是上一个场景留下的 $S$。

### 3.3 真实代码：改动只有一个循环

这个想法在实现上极小。`core/adapter/base_adapter.py`：

```python
def forward(self, x):
    for _ in range(self.steps):                      # K 次
        outputs = self.forward_and_adapt(x, self.model, self.optimizer)
    return outputs                                   # 只返回最后一次
```

`self.steps` 来自配置项 `OPTIM.STEPS`（默认 1，即原方法）。**K=1 时执行路径与原实现完全一致**，不会改变任何行为（回归实测 78.96 / 77.39，与基线 78.99 / 77.48 的差异纯属 GPU 非确定性）。

单轮内部（`core/adapter/TRIBE.py::update_model`）做的事情：

```
① eval 模式前向教师 → 得到 logits，argmax 得伪标签 p̂
② 用 p̂ 作为"类别身份证"，把本批样本分配到各自的逐类统计量上，更新之
③ train 模式前向学生（输入强增强图）→ 交叉熵损失（学生 vs p̂）
④ train 模式前向锚 → MSE 损失（教师输出 vs 锚输出）
⑤ 反向传播，只更新 BN 的缩放/偏移参数
⑥ 外层把 ① 的 logits 交出去（下一轮会重新执行 ①，此时统计量已更新）
```

### 3.4 三个必须澄清的细节

#### (a) 为什么"再算一遍"就能变好？——吸收率

这是最容易被追问的一点。看逐类统计量的更新公式（`core/utils/balanced_bn_pyv.py`）：

$$\mu_k \leftarrow \mu_k + \eta \sum_{i \in \text{class } k}\left(x_i - \mu_k\right) = \mu_k + \eta\, n_k \left(\bar{x}_k - \mu_k\right)$$

**注意是求和、不是求平均**，所以实际步长是 $\eta \cdot n_k$（$n_k$ 为该类在这一批里出现的次数），而不是 $\eta$。

这一点很关键：$\eta$ 配置成 0.01 看起来"只挪 1%"，但因为按 `sum` 聚合，**实际一步能吃掉 $1-(1-\eta n_k)$ 的差距**。本实验的批大小是 64，且该协议的批次由 Dirichlet 分层抽样构造（`LabelDirichletDomainSequenceLongTailed`），**同一批里各类的份额高度不均**——按采样器的构造方式，一个批次往往由少数几个类占据大部分位置，因此 $n_k$ 可以达到几十，$\eta n_k$ 远大于 0.01。

于是 K 轮之后的剩余差距约为 $(1-\eta n_k)^K$。把实测增量代进去反推，本实验的有效吸收率约 $\eta n_k \approx 0.32$：

| K | 剩余差距 | 累计吸收 $1-(1-0.32)^K$ | 实测 micro 增量（I.F.=10） |
|---|---|---|---|
| 1 | 0.68 | **32%** | — |
| 2 | 0.46 | **54%** | +3.58 |
| 3 | 0.31 | **69%** | +2.51 |
| 4 | 0.21 | **79%** | +1.77 |

> 通俗说法：**"调焦距"一次只能调准三分之一，那就多调几次。** 三次之后已经对准七成。
>
> ⚠️ 这是**一阶近似**：真实迭代中特征本身也在随参数变化，$n_k$ 每批都不同，所以不是严格等比数列。
> 但它准确预测了"边际收益递减"这一实测规律——**累计吸收 32→54→69→79%，而实测增量 3.58→2.51→1.77 也同步放缓**，两者形状吻合。这支持"迭代在向定点收敛"的解释（见 §5.1）。

#### (b) 这样做"合法"吗？会不会偷看答案？——不，这是 transductive

学术上把"用当前这批无标签数据来辅助预测当前这批数据"的做法叫 **transductive（转导式）**。它**不违规**，理由：

1. **没有用到任何标签**。全程只有模型自己的预测。
2. **这是 TTA 领域的通行做法**。TENT、BN-adapt 等主流方法的预测同样使用当前批次的统计量——它们也是"用这批数据校准，再预测这批数据"。IABA 只是把这件事**做 K 次**而不是 1 次。
3. **不跨批次偷看未来**。第 k 轮只用到本批数据，没有用后面还没到的数据。

> 通俗说法：**开卷考试里允许翻书，IABA 只是多翻了两遍。** 它没有拿到标准答案。

#### (c) 迭代多次会不会越跑越偏？——锚定是安全绳

会。这正是**多步自训练**的经典风险：模型用自己的预测当答案反复训练，错误会被放大（确认偏差），最终崩掉。

TRIBE 的**锚定损失**（与冻结的源模型做 MSE）恰好抑制了这一点：参数 $\theta$ 的漂移被锚约束住，而统计量 $S$ 可以自由收敛。

> 一句话概括这个设计：**"锚定参数，迭代统计"（anchor the parameters, iterate the statistics）。**
>
> 我们做了对照实验来验证这不是空话——把 TRIBE 换成**没有锚定的 TENT**，同样跑 K=2，结果直接崩到 **16.8% / 19.2%**（两次运行，接近随机猜）。见 §4.4。

## 4. 实验：从 79% 到 87%

### 4.1 实验设置

| 项目 | 设置 |
|---|---|
| 数据集 | CIFAR-10-C（另加 CIFAR-100-C 交叉验证） |
| 损坏 | 15 种 × severity 5，按顺序流式处理 |
| 协议 | GLI-TTA-F（全局类不平衡，类比例在 15 个场景间固定） |
| 不平衡因子 | I.F. = 1 / 10 / 100 |
| 主干网络 | ResNet-50（`Standard`，robustbench 预训练，corruption 威胁模型） |
| 批大小 | 64 |
| 随机种子 | 425（另加 0 / 1 做多种子验证） |
| 超参数 | ETA=0.01, GAMMA=0.0, H0=0.05, LAMBDA=0.5（CIFAR-10 默认） |
| 硬件 | RTX 5070 Ti，torch 2.8.0+cu128 |

**各协议的实际样本量**（由采样器公式计算，长尾裁剪后）：

| 协议 | 每场景样本 | 最稀类每场景 | 总样本 | 相对规模 |
|---|---|---|---|---|
| I.F.=1（均衡） | 10,000 | 1,000 | 150,000 | 1.0× |
| I.F.=10 | 4,084 | 100 | ~61,300 | 0.41× |
| I.F.=100 | 2,478 | **10** | ~37,200 | 0.25× |

> 注意最后一行：I.F.=100 时**最稀的类在整个场景里只有 10 张图**。这是理解后文"为什么尾类难救"的关键。

### 4.2 主结果：三个不平衡水平 × 四个迭代次数

准确率（%），格式为 **micro / macro**：

| 每批迭代 K | I.F.=1（均衡流） | I.F.=10 | I.F.=100 |
|---|---|---|---|
| **1**（原 TRIBE） | 83.92 / 83.92 | 78.99 / 77.48 | 80.19 / 75.30 |
| **2** | 87.51 / 87.51 | 82.57 / 81.52 | 82.87 / 79.07 |
| **3** | 89.08 / 89.08 | 85.08 / 84.63 | 84.56 / 81.36 |
| **4** | **89.89 / 89.89** | **86.85 / 86.81** | **84.99 / 83.08** |

换算成相对原方法的增益：

| K | I.F.=1 | I.F.=10 | I.F.=100 |
|---|---|---|---|
| 2 | +3.59 | +3.58 / +4.04 | +2.68 / +3.77 |
| 3 | +5.16 | +6.09 / +7.15 | +4.37 / +6.06 |
| 4 | +5.97 | **+7.86 / +9.33** | +4.80 / +7.78 |

三个观察：

1. **所有 9 个格子都是正收益，没有一个例外。** 这是最重要的结论——方法不是"在某个设置下碰巧有用"。
2. **K=2 就拿走了大部分收益**（约 45~60%），K 继续增大仍稳步提升但增速放缓，与 §3.4(a) 的吸收率曲线吻合。
3. **I.F.=1 时 micro 与 macro 完全相等**（83.92/83.92、89.89/89.89）。这是合理的：类别均衡时两类指标定义上就退化为同一个数。这也顺便验证了指标计算没写错。

用"错误率相对下降"这个更公平的口径来看（消除基线高低的影响）：

| 设置 | K=1 错误率 | K=4 错误率 | 相对下降 |
|---|---|---|---|
| I.F.=1（micro） | 16.08 | 10.11 | **37.1%** |
| I.F.=10（micro） | 21.01 | 13.15 | **37.4%** |
| I.F.=10（macro） | 22.52 | 13.19 | **41.4%** |
| I.F.=100（micro） | 19.81 | 15.01 | 24.2% |
| I.F.=100（macro） | 24.70 | 16.92 | 31.5% |

**诚实说明**：增益在中等不平衡（I.F.=10）时最大，均衡流（I.F.=1）和重不平衡（I.F.=100）略小。I.F.=100 收益偏小的原因见 §6 的讨论——主要是因为最稀类每场景只有 10 张图，**迭代次数再多也变不出数据来**。

### 4.3 关键消融：排除"只是统计更新更快了"这个解释

有人会问：既然多迭代几轮等于让统计量更新得更快，那我**直接把动量调大**（一次迈大步）不就行了？**不行，而且这是我们最重要的对照实验。**

| 配置 | micro | macro | 说明 |
|---|---|---|---|
| K=1，ETA=0.01（原方法） | 78.99 | 77.48 | 基准 |
| **K=1，ETA=0.02** | **78.31** | **77.34** | 单次步长翻倍 → **反而变差** |
| K=2，ETA=0.01 | **82.57** | **81.52** | 总吸收量**更少**，却**大幅变好** |

算一下吸收量就明白了：

- ETA=0.02、K=1：吸收 $1-(1-0.64) = 64\%$
- ETA=0.01、K=2：吸收 $1-(1-0.32)^2 = 54\%$

**K=2 吸收得更少，却好 4 个百分点。** 所以收益**不可能**来自"统计涨得更快"，只能来自**迭代结构本身**：每一轮都用"已经部分校准过的眼睛"重新看图，于是**伪标签的质量也在提升**；下一轮的校准因此打在了更正确的目标上。

> 通俗说法：**不是"步子大不大"的问题，是"边走边看"的问题。** 蒙着眼睛大步走会摔；睁眼小步走能到。

### 4.4 反例对照：没有锚定就会崩

| 方法 | K=1 | K=2 | 结果 |
|---|---|---|---|
| **TRIBE**（有锚定） | 78.99 / 77.48 | **82.57 / 81.52** | 大幅提升 |
| **TENT**（无锚定） | ~21.9（错误率 78.15，论文报） | **16.83 / 19.21**（两次运行） | **崩溃**，接近随机 |

这一格是整篇工作的逻辑支点：它证明了 **"锚定损失是让批内迭代可行的必要条件"**，而不是可有可无的正则项。多步自训练本身是危险的，IABA 之所以成立，是因为它站在 TRIBE 的锚定机制上。

### 4.5 跨数据集：CIFAR-100-C（100 类）

类别数从 10 增到 100，逐类统计量变得**更稀疏**（I.F.=10 时平均每类每场景只有约 39 张图，最稀类 10 张）。按理论，冷启动问题应该更严重，IABA 收益应该更大。

**实测并没有。**

| 配置 | micro | macro | 增益 |
|---|---|---|---|
| TRIBE K=1 | 66.10 | 64.68 | — |
| IABA K=2 | **67.07** | **65.44** | **+0.97 / +0.76** |

收益方向正确（仍是双赢），但幅度只有 CIFAR-10 同协议（+3.58/+4.04）的**五分之一到四分之一**。

**解释**：CIFAR-100 的源模型本身弱得多（基线 66% vs CIFAR-10 的 79%），意味着**伪标签错误率更高**。多步迭代的收益来自"用更好的伪标签再训练一次"，而如果伪标签本身就不可靠，迭代就只能反复强化噪声。

> 结论：**"类越多、统计越稀疏 → 收益越大"这个推论只在伪标签质量足够时成立。** 这是一个有价值的负向发现——它说明 IABA 的瓶颈不是统计量的更新速度，而是伪标签的信噪比。

### 4.6 多种子稳健性

I.F.=10、K=2，换三个随机种子：

| 种子 | micro | macro |
|---|---|---|
| 425（主实验） | 82.57 | 81.52 |
| 0 | 83.10 | 82.21 |
| 1 | 83.26 | 82.21 |
| **均值 ± 极差** | 82.98（±0.35） | 81.98（±0.35） |

增益幅度（+3.5~4.3pt）远大于种子间波动（±0.35），结论稳健。

> 附注：早先估的"运行噪声 ±0.1"偏乐观，那是单任务独占 GPU 时的数字；两个实验并行跑时 CUDNN 的自动调优互相干扰，会把波动放大到 ±0.3~0.7。**判读小差异时务必让实验独占 GPU。**

### 4.7 换协议：GLI-TTA-V（每场景随机类比例）

前面所有实验都是 GLI-TTA-**F**（F = Fixed，15 个场景的类比例固定不变）。GLI-TTA-**V**（V = Variable）让每个场景的类比例**随机打乱**，更接近真实世界的不可预测性。

| 配置 | micro | macro | 增益 |
|---|---|---|---|
| TRIBE K=1 | 78.94 | 77.48 | — |
| IABA K=2 | **83.07** | **81.50** | **+4.13 / +4.02** |

增益与 F 协议（+3.58/+4.04）基本一致。**说明 IABA 不依赖"类比例固定"这个假设**，机制是通用的。

### 4.8 计算成本

| 配置 | 单样本耗时（秒） | 相对 K=1 | 对标 |
|---|---|---|---|
| K=1（TRIBE） | ~0.0040 | 1.0× | — |
| K=2 | ~0.0072 | 1.8× | — |
| K=3 | ~0.010 | 2.6× | — |
| K=4 | ~0.014 | 3.5× | CoTTA 0.019 / PETAL 0.0163 |

- **显存不增加**（同一批数据重复前向，没有额外缓存）。
- 耗时近似线性于 K，与"K 次前向 + K 次反向"的预期一致。
- 即使 K=4（0.014 s/样本）仍**比 CoTTA 快**，K=2~3 是性价比最高的工作点。

> 数据来源说明：K=2 / K=4 的数值取自早前独占 GPU 的实测；K=1 参照同协议基线实测
> （CIFAR-100 基线 0.0044、GLI-TTA-V 基线 0.0046，取 0.0040 为保守参照）；K=3 为按线性内插。
> 本轮有几个实验是两两并行跑的，实测值被拖慢到 0.013~0.030，**不能用于横向比较**。

### 4.9 收敛趋势一览

把 I.F.=10 的曲线画出来（micro）：

```
准确率(%)
 87 ┤                                    ● 86.85 (K=4)
 85 ┤                        ● 85.08 (K=3)
 83 ┤            ● 82.57 (K=2)
 81 ┤
 79 ┤  ● 78.99 (K=1)

       K=1      K=2      K=3      K=4
```

增量 3.58 → 2.51 → 1.77，逐次递减但始终为正，形状与 §3.4(a) 的 $1-(1-\eta n_k)^K$ 一致。若要继续提升，应转向攻击"伪标签质量"而非继续加大 K。

## 5. 为什么有效：原理层面的解释

### 5.1 定点迭代（fixed-point iteration）视角

数学上，IABA 是在求一个**自洽解**：

> 找一组统计量 $S^*$，使得"用 $S^*$ 归一化这批数据得到的预测"与"用这批数据（按该预测分组）重新算出的统计量"相互一致。

这正是**定点迭代**的形式：$S^{(k+1)} = F(S^{(k)})$，收敛到 $S^* = F(S^*)$。原方法只走了一步就停了；IABA 多走几步逼近不动点。

> 通俗说法：**"鸡生蛋"的循环。** 要准确预测就得有正确的统计量，要有正确的统计量就得先准确预测。解法是**交替进行、逐步逼近**，而不是指望一次就对上。

这个视角还解释了三件事：为什么 K=1 差（离不动点最远）、为什么增益递减（越接近不动点每步推进越小）、为什么必须"每轮重新预测"（否则就不是在迭代同一个映射）。

### 5.2 与"加大动量"的对照（一个失败的替代方案）

在想到 IABA 之前，我们先试了另一条更直接的路：**检测到场景切换时，临时把 BN 动量放大 8 倍，持续 10 个批次**，让旧统计量被快速冲掉（配置项 `SHIFT_WARMUP`）。

检测机制是有效的（用相邻批次特征均值的相对距离做信号：场景内约 0.06，切换点 0.44~0.46，阈值 0.4，能准确触发）。但结果：

| 配置 | I.F.=10 | I.F.=100 |
|---|---|---|
| 基线 | 78.99 / 77.48 | 80.19 / 75.30 |
| + SHIFT_WARMUP（动量 ×8, 10 批） | 78.11 / 76.94（**-0.85 / -0.44**） | 78.75 / 74.34（**-1.44 / -0.96**） |

**明确负收益。** 原因：动量放大期间，统计量是用**当前还很差的伪标签**分组计算的，等于把噪声放大 8 倍灌进去。

**这两条路的对比是本报告最有说服力的部分**：

| 方案 | 做法 | 类比 | 结果 |
|---|---|---|---|
| SHIFT_WARMUP | 一次迈大步 | 蒙眼大步走 | ❌ 摔倒 |
| **IABA** | 多走小步，每步重新看路 | 睁眼小步走 | ✅ 到终点 |

> 结论：**低质量的校准做 1 次和做 8 次一样糟；只有"校准 → 重新预测 → 再校准"的闭环才能把噪声变成信息。**

这也是为什么 §4.3 的 ETA=0.02 消融如此重要——它和 SHIFT_WARMUP 一起，把"只是更新更快"这个解释彻底排除了。

### 5.3 与 TENT / BN-adapt 的关系

| 方法 | 每批做什么 | 相当于 |
|---|---|---|
| BN-adapt | 用当前批统计量直接归一化（不学习） | IABA 的思想雏形，但只做 1 次且无参数更新 |
| TENT | 用熵最小化微调 BN 参数，K=1 | 有学习，但"先预测后更新"，且无锚定 |
| **IABA** | 在 TRIBE 上把"预测-更新"闭环重复 K 次 | **把 transductive 归一化推到它的自然终点** |

一句话定位：**IABA 不是一个新模块，而是对"TTA 到底允许用多少当前批次信息"这个问题给出的一个更彻底的答案。** 它不加参数、不改结构、不改损失，只改了执行顺序的次数。

## 6. 局限与边界

诚实列出，供答辩时主动交代：

| 局限 | 说明 | 影响 |
|---|---|---|
| **只在一个数据集上充分验证** | CIFAR-10-C 全面；CIFAR-100-C 只测了 K=2 | ImageNet-C 未做（需 ~12GB 数据，且源模型精度仅约 40%，预期收益受伪标签噪声制约） |
| **单种子为主** | 主表是 seed 425，稳健性用 3 个种子补了 K=2 | 结论方向稳健，但 ±0.35 的波动意味着 **<0.5pt 的差异不可信** |
| **类别极多时收益衰减** | CIFAR-100 上仅 +0.97/+0.76 | 瓶颈从"统计收敛"转移到"伪标签质量" |
| **计算线性增长** | K=4 约 3.5 倍耗时 | 高吞吐场景下 K=2 是更实际的默认值 |
| **依赖锚定机制** | 换到 TENT 上直接崩溃 | 方法不能脱离 TRIBE 及其同类锚定框架单独使用 |
| **未解决场景切换根本问题** | IABA 加速了爬坡，但"旧统计量污染新场景"依然存在 | 真正的解法可能是场景检测 + 统计重置，本工作只做到"加速恢复" |

| 场景 | 耗时 |
|---|---|

## 8. 术语表

| 术语 | 全称 / 英文 | 一句话解释 |
|---|---|---|
| **TTA** | Test-Time Adaptation | 测试阶段只用无标签数据就地调整模型 |
| **IABA** | Iterated Intra-Batch Adaptation | 本报告的方法：同一批次内"预测-校准"迭代 K 次 |
| **BN** | Batch Normalization | 把每层输出拉回统一尺度，需维护均值和方差 |
| **running statistics** | 运行时统计量 | BN 里记录的"典型均值/方差"，测试时使用 |
| **momentum** | 动量（η） | 滑动平均的更新步长，0.01 = 每次挪 1% |
| **Balanced BN** | 均衡批归一化 | 每类各维护一份统计量，预测时等权平均，防头类淹没尾类 |
| **伪标签** | pseudo-label | 模型自己猜的标签，用来当"答案"训练自己 |
| **确认偏差** | confirmation bias | 模型反复强化自己的错误猜测，越错越自信 |
| **锚定损失** | anchor loss | 与冻结的源模型输出做 MSE，防止参数跑偏 |
| **micro 准确率** | instance-wise accuracy | 所有样本一视同仁的总正确率，偏向头类 |
| **macro 准确率** | category-wise accuracy | 每类算完再平均，每类等权，能暴露尾类被牺牲 |
| **I.F.** | Imbalance Factor | 最多类 ÷ 最少类的样本数之比 |
| **长尾 / 头类 / 尾类** | long-tail / head / tail | 样本数从多到少呈长尾分布；多的叫头类，少的叫尾类 |
| **corruption** | 损坏 | 噪声、模糊、天气、压缩等使图片"变脏"的扰动 |
| **severity** | 严重程度 | CIFAR-C 系列的 1~5 级，5 最严重 |
| **GLI-TTA-F / V** | Global & Local Imbalanced TTA | F=类比例固定（Fixed），V=随机（Variable） |
| **transductive** | 转导式 | 用当前这批无标签数据辅助预测当前这批（TTA 通行做法，不违规） |
| **定点迭代** | fixed-point iteration | 反复施加同一映射直到自洽，$S=F(S)$ |
| **消融实验** | ablation study | 去掉/替换某个组件，看指标变化，判断它是否真有用 |

## 9. 常见追问（答辩用）

**Q1：这不就是多跑几遍吗？有什么技术含量？**

看起来简单，但**这个"简单"是结果，不是前提**。我们做了三个对照才确认它成立：(1) 加大动量（单次迈大步）是**负收益**，说明不是"更新更快"；(2) 换到无锚定的 TENT 上 K=2 直接崩到 17~19%，说明**必须先有锚定机制**；(3) 收益随 K 按吸收率曲线递减，符合定点迭代的预测。**能用一个循环换来 7.86pt，恰恰说明原始实现里"先预测后更新"是个真实的顺序缺陷。**

**Q2：K 次迭代算不算用了测试数据的标签？**

不算。全程无标签，只用了模型自己的预测。这种"用当前批校准当前批"的做法是 TTA 领域的通行设定（TENT、BN-adapt 同样如此），学术上叫 transductive。我们也没有跨批次偷看未来数据。

**Q3：为什么不直接把 K 设得很大，比如 K=10？**

三个原因：**(a) 边际收益递减**（3.58 → 2.51 → 1.77，K=4 后每次提升已不足 1pt）；**(b) 计算线性增长**（K=10 就是 10 倍耗时，失去实用价值）；**(c) 伪标签噪声会累积**——迭代越久，被强化的错误越多，存在过拟合风险。K=2~3 是性价比最高的区间。

**Q4：为什么 CIFAR-100 上收益小这么多？这是不是说明方法不通用？**

方向仍然正确（+0.97/+0.76，双赢），幅度小是因为 **CIFAR-100 的源模型本身只有 66% 准确率，伪标签错误率高**。IABA 的收益机制是"用更好的伪标签再训练一轮"，伪标签不可靠时这个杠杆就失效了。这反而是一个有价值的诊断：**它把瓶颈明确指向了伪标签质量，而不是统计收敛速度。**

**Q5：和 CoTTA、PETAL 这些方法比怎么样？**

不是替代关系，而是**可叠加**关系。CoTTA（0.019 s/样本）、PETAL（0.0163）靠额外的教师集成 / 贝叶斯建模提升稳健性；IABA 走的是"不增加任何额外模块的执行顺序优化"，K=2 时 0.0072 s/样本，**比它们都快**。原则上 IABA 也可以叠加到它们之上（把它们各自的单轮更新也迭代 K 次），这是后续可做的方向。

**Q6：为什么 I.F.=1 时 micro 和 macro 完全一样？**

因为类别均衡时，"所有样本的平均正确率"和"各类正确率的平均"在数学上是同一个量。这同时也验证了我们的指标实现没有写错。

**Q7：实验结果可信吗？有没有多重比较问题？**

主结论（3 个不平衡水平 × 3 个 K 值，共 9 个格子）**全部为正**，且增益幅度（+2.7~+9.3pt）远大于种子间波动（±0.35）与运行噪声（<0.1，独占 GPU 时）。即使按最保守的多重比较修正也站得住。但我们仍标注了：**<0.5pt 的差异不作结论**。
